# Into the Fray

Into the Fray: an online card table for Marvel Champions, played
in the browser, solo or multiplayer, as a pure sandbox (no rules
automation).

See [DEVELOPMENT.md](DEVELOPMENT.md) for setup, configuration, card
packs, CI and deployment.

## Tech stack

- Backend: Go (standard library `net/http`, WebSocket), stateless;
  Redis holds game state, connection leases and pub/sub
- Frontend: TypeScript, Svelte 5 + Vite, static SPA on GitHub Pages
- Card data: JSON packs generated by `cmd/packgen` from public card
  sources and hand-curated files; images on `img.intothefray.xyz`

## Build & run

```bash
make dev          # Redis + Caddy in containers, Air, web build
make test         # go test -race -shuffle=on ./...
make check        # tests, web-check, then golangci-lint
make web-check    # svelte-check, eslint + prettier, vitest
make packs        # card packs; needs packs/images/manifest.json
```

## Modules

- `cmd/intothefray/` — server entry point and `healthcheck` subcommand
- `cmd/packgen/` — card pack generator (`make packs`)
- `internal/config/` — configuration from environment variables
- `internal/decks/` — deck import from marvelcdb
- `internal/game/` — pure game engine (lobby, setup, actions, undo, views)
- `internal/server/` — HTTP API, WebSocket endpoint, cross-instance hub
- `internal/store/` — Redis game store, connection leases, pub/sub
- `internal/version/` — build commit, served by `GET /api/version`
- `internal/pack/` — card pack schema and catalog
- `internal/packgen/` — generator internals (sources, curated data, build)
- `packs/` — `curated/` hand-written data, `dist/` generated JSON
  (committed, never edited by hand), embedded by `packs.go`
- `web/` — Svelte SPA (standalone pnpm project) and its `Caddyfile`;
  `seo.ts` writes the share previews at build, `images/` holds the
  sources of the share images
- `Dockerfile`, `compose.yaml` — server image and local stack
- `mise.toml` — pinned node and pnpm versions (local and CI)
- `scripts/`, `.casper.json` — optional Casper workspace support
- `.github/workflows/ci.yml` — checks, then image, Pages and backend
  deployment on `main`

## Conventions

- Line length limits for readability:
  - Text / Markdown: 80 columns max
  - Code: 120 columns max
- Follow standard Markdown conventions: blank line
  before and after headings, blank line before and
  after lists, fenced code blocks with a language tag
- Always use the latest LTS or stable version of
  languages, frameworks, and libraries. Check the
  official documentation or use available tools
  (e.g. context7) to verify current versions before
  choosing a dependency.
- All project text is in English: code, comments,
  docs, UI, commit messages.
- Never commit `docs/` (design specs, plans,
  prototypes): it is gitignored and stays local.
- The design lives in `docs/superpowers/specs/`, the
  implementation plans in `docs/superpowers/plans/`;
  read them before changing behaviour.
